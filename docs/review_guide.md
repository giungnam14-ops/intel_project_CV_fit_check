# FitCheck AI 리뷰 가이드 (Review Guide)

안녕하세요! FitCheck AI 프로젝트에 관심을 가져주셔서 감사합니다. 
현재 본 프로젝트는 **실제 코드 구현 전 단계**이며, 기획과 요구사항, 아키텍처 설계를 문서 기반 MVP 형태로 먼저 구체화한 상태입니다. 

효율적인 검토와 피드백을 위해 아래의 안내서를 참고해 주시기 바랍니다.

---

## 📖 1. 권장 문서 읽기 순서 및 역할

다음 순서대로 문서를 읽어보시면 프로젝트의 배경부터 세부 로직까지 흐름을 끊기지 않고 파악하실 수 있습니다.

1. **`docs/project_summary.md` (먼저 읽어주세요!)**
   - 프로젝트 전체를 한눈에 파악할 수 있는 1~2페이지 분량의 최종 요약서입니다.
2. **`docs/problem.md`**
   - 타겟 사용자의 Pain Point와 해결 가치를 정의한 문제 정의서입니다.
3. **`docs/prd.md`**
   - 사용자 스토리와 MVP 핵심 기능 통과 조건(Acceptance Criteria)을 정의한 요구사항 명세서입니다.
4. **`docs/decision_spec.md`**
   - 자세 판정의 핵심이 되는 임계값(각도), 국면 정의, 오탐 방지 규칙 등을 구체화한 명세서입니다.
5. **`docs/trd.md`**
   - MediaPipe 및 OpenCV 연동, 벡터 기반 각도 계산 등 기술적 구현 방안을 정리한 설계도입니다.
6. **`docs/success.md`**
   - 프로젝트의 북극성 지표와 정량적/정성적 성공 기준을 정의한 문서입니다.
7. **`architecture/dfd.md`**
   - 시스템 내 데이터의 흐름과 처리 과정을 구조화한 데이터 흐름도입니다.
8. **`architecture/sequence.md`**
   - 사용자와 시스템, 각 컴포넌트 간의 상호작용 순서를 시각화한 시퀀스 다이어그램입니다.

## 🎯 2. 핵심 검토 포인트

리뷰 시 다음 세 가지 관점을 중점적으로 살펴봐 주시면 큰 도움이 됩니다.
- **가치 (Value)**: 해결하려는 문제와 솔루션이 연결되며, 사용자에게 실질적인 가치를 주는가?
- **실현 가능성 (Feasibility)**: 제안된 기술 스택(MediaPipe 등)과 아키텍처로 기능 구현이 가능한가?
- **명확성 (Clarity)**: 판정 기준(`decision_spec.md`)과 평가 지표(`success.md`)가 개발자 입장에서 혼선 없이 코딩할 수 있을 만큼 명확한가?

---

## ✅ 3. 현재 확정된 것 vs ❓ 4. 아직 결정이 필요한 것

**현재 확정된 것**
- 서비스 기획 및 문제 정의 (로컬 중심 MVP)
- 핵심 기술 스택 (Streamlit, OpenCV, MediaPipe Pose)
- 스쿼트 자세 판정 로직 초안 (각도 기준, 스무딩, 신뢰도 보류 등)
- 데이터 수집 및 평가 전략 (튜닝용 vs 검증용 데이터 분리)

**아직 결정이 필요한 것 (튜닝 예정)**
- `decision_spec.md`에 명시된 구체적인 각도 임계값 ($110^\circ$, $45^\circ$ 등)의 미세 조정 여부
- 스무딩 처리에 필요한 최적 프레임 수 (현재 5프레임 기준으로 설계되었으나 테스트 후 변경 가능)

## 📝 5. 피드백을 받고 싶은 질문 목록

멘토님, 강사님, 그리고 팀원분들의 날카로운 피드백을 기다립니다!

1. **[기획 타당성]** 이 주제와 타겟 사용자 설정이 현실적으로 니즈가 있다고 생각하시나요?
2. **[일정 현실성]** 개발 환경 세팅부터 로직 튜닝까지 3주(16일) 안에 구현 가능한 적절한 범위인가요? 
3. **[기능 범위]** 현재 F1(관절 시각화) 및 F2(판정/코칭) 로 한정된 기능 범위(MVP)가 적절한가요? 혹은 버려야 할 로직이 있을까요?
4. **[오탐 방지]** `decision_spec.md`에서 제안된 '신뢰도 보류'나 '이동 평균 스무딩' 로직이 실제로 오탐을 줄이는 데 효과적일까요? 개선할 기술적 팁이 있다면 조언 부탁드립니다.
